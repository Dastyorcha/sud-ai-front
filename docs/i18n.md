# i18n & locale routing

A lightweight, **custom** i18n layer (no library — no `react-i18next`, no `i18next`). Locale lives in the URL as the first path segment. `CLAUDE.md` and `docs/architecture.md` link here; `ui-designer` enforces "every string through `t()`".

## Locale model

`src/shared/lib/i18n/locale.ts`:

- `LOCALES = ["uz", "en", "ru"] as const` and `type Locale = (typeof LOCALES)[number]`.
- `DEFAULT_LOCALE = "uz"` — the product default (uz lotin).
- `LOCALE_LABELS: Record<Locale, string>` — native names for the switcher (`O'zbekcha` / `English` / `Русский`).
- `LOCALE_STORAGE_KEY` — the `localStorage` key the last-picked locale is persisted under (UI preference only, not business data).
- `isLocale(value): value is Locale` — narrows an arbitrary route param/string.

## Routing

Every route is mounted under `/:lang/*` in `src/app/app.tsx`:

- `/` redirects to `/{preferred}` — the `localStorage` locale if valid, else `DEFAULT_LOCALE`. The current query string is preserved.
- `/:lang` is validated with `isLocale()`. A supported locale provides `LocaleProvider` and renders the matched child route (`<Outlet />`). An unsupported locale (e.g. `/xx`) renders the 404 page directly (in a `DEFAULT_LOCALE` context, so it still reads).
- `ROUTE_PATHS` in `src/shared/constants/route-paths.ts` stays **locale-less** (e.g. `TOOLS: "/tools"`) — the router registers each as a route nested under `/:lang`. Never hardcode a path in a `<Route>`/`<Link>`/`navigate()`.
- `withLocale(locale, path)` (also in `route-paths.ts`) builds the concrete, navigable URL: `withLocale("uz", ROUTE_PATHS.TOOLS)` → `/uz/tools`. Use it for every in-app link/navigation call — see `src/shared/custom/lang-switcher.tsx` and the auth forms (`src/shared/components/pages/auth/*`) for the pattern.

## Message shape

`src/shared/lib/i18n/messages/uz.ts` is the **source of truth**:

```ts
export const uz = {
  common: { loading, retry, close, save, cancel, back, search, logout, … },
  nav: { dashboard, users },
  pages: { dashboard, users, login, register, resetPassword, selectOrganization, tools, forbidden, notFound, maintenance },
  enums: { roles: {…}, courtRoles: {…}, courtType: {…}, caseType: {…}, caseStatus: {…}, participantRole: {…}, hearingStatus: {…}, segmentStatus: {…}, documentStatus: {…}, jobStatus: {…} },
  errors: { notFoundTitle, notFoundDescription, genericTitle, genericDescription, … },
  langSwitcher: { label, changeLanguage },
  users: { description, active, inactive, columns: { name, role, status, lastLogin, email, phone } },
};
export type Messages = typeof uz;
```

`en.ts` and `ru.ts` each declare `export const en/ru: Messages = { ... }` — TypeScript enforces the **exact same shape**, so a key present in `uz.ts` but missing (or misspelled) in `en.ts`/`ru.ts` is a compile error. **Adding a key means updating all three files in the same change.**

`enums.*` sub-keys mirror the **exact enum values** from `src/shared/types/enums.ts` (e.g. `enums.roles.admin`) — never a separate `*_LABELS` map. This lets a consumer build the key straight from the enum value:

```ts
t(`enums.roles.${user.role}` as MessageKey);
```

`src/shared/lib/i18n/messages/index.ts` aggregates them into `MESSAGES: Record<Locale, Messages>` and derives `MessageKey` — a template-literal union of every dot-path to a leaf (e.g. `"pages.dashboard"`, `"enums.roles.admin"`) computed from `Messages`, so `t()` gets autocomplete and a typo is a type error.

## `useTranslation()` API

`src/shared/lib/i18n/locale-context.tsx`:

```ts
const { locale, t, formatMoney, formatDate, formatNumber } = useTranslation();
```

- `locale: Locale` — the active locale, derived from the `:lang` route param (`LocaleProvider` reads it via `useParams`).
- `t(key: MessageKey, vars?: Record<string, string | number>): string` — dot-path lookup with `{var}` interpolation (`t("errors.notFoundDescription")`, or `t("some.key", { name: "Ali" })` for a template containing `{name}`). Falls back to the `uz` string, then to the raw key, if a locale is missing a translation at runtime.
- `formatMoney(value)` / `formatDate(value, options?)` / `formatNumber(value, options?)` — locale-bound wrappers around `src/shared/lib/i18n/format.ts` (below).

`useTranslation()` throws if called outside a `LocaleProvider` — every route in the app is inside one (mounted once per `/:lang` match in `app.tsx`), so this only fires from a coding mistake.

## Formatting (`format.ts`)

- `formatMoney(value, locale)` — grouped digits, suffixed with a localized currency word. Adjust `format.ts` to your project's currency/locale conventions.
- `formatDate(value, locale, options?)` — `Intl.DateTimeFormat`; `options` overrides the default `year/month/day` numeric format.
- `formatNumber(value, locale, options?)` — plain `Intl.NumberFormat` passthrough for generic numbers.

## `LangSwitcher`

`src/shared/custom/lang-switcher.tsx` — a shadcn `DropdownMenu` (`Button` trigger showing the current locale code). Selecting a locale:

1. Writes it to `localStorage` (`LOCALE_STORAGE_KEY`).
2. Swaps only the `:lang` segment of the current path, keeping the rest of the path and the query string — so switching locale on `/uz/tools?tab=colors` goes to `/en/tools?tab=colors`, not back to the dashboard.

Wired into the public header (`src/shared/components/layout/header/app-header.tsx`) and showcased in the `/tools` playground.

## Adding a string (checklist)

1. Add the key to `src/shared/lib/i18n/messages/uz.ts` under the right namespace (`common`, `nav`, `pages`, `enums`, `errors`, `langSwitcher` — add a new namespace only if none fits).
2. Mirror the key in `en.ts` and `ru.ts` with real translations (not English placeholders) — `tsc -b` fails until both match the `uz` shape.
3. Call it with `useTranslation().t("namespace.key")` in the component. Never hardcode copy.
4. If it's a new enum, add its values to `enums.*` in all three files using the enum's exact string values as keys.

## Single-locale projects

If your project only needs one language, drop `en`/`ru` from `LOCALES` in `locale.ts` and the corresponding message files — the rest of the mechanism (typed `t()`, `/:lang` routing) still works with a single locale.

## Non-goals

No SEO/hreflang (still no SEO in this admin panel), no RTL (all three shipped locales are LTR). If a full `react-i18next`-style library is ever wanted, this layer's `t()`/`useTranslation()` shape is swap-compatible.
